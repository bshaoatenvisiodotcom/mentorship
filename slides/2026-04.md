# <!-- fit --> Flexible JavaScript

---

- Primitives(Simple values) can behave like objects
- Methods can be added on prototypes
- Syntax gets weird fast

---

## `Number.prototype`

```js
Number.prototype.add = function (x) {
  return this + x;
};
```

```js
(8).add(2);
// 10
```

---

## Calling a Number Method

```js
(8).add(2);
8..add(2);
8['add'](2);
```

- `8.add(2)` is parsed as a decimal literal
- Wrap it, use `..`, or use brackets

---

## Chaining

```js
Number.prototype.subtract = function (x) {
  return this - x;
};

(8).add(2).subtract(4);
// 6
```

---

## Why It Works

- Number values are primitives
- Property access triggers boxing
- JavaScript creates a temporary `Number` object

---

## Another Example

```js
Number.prototype.iterate = function () {
  const result = [];

  for (let i = 0; i <= this; i += 1) {
    result.push(i);
  }

  return result;
};
```

```js
(8).iterate();
// [0, 1, 2, 3, 4, 5, 6, 7, 8]
```

---

## Getter Trick

- Methods need `()`
- Getters run on property access
- That makes chained property reads possible

---

## `Object.defineProperty`

```js
Object.defineProperty(Number.prototype, 'double', {
  get() {
    return this + this;
  }
});

Object.defineProperty(Number.prototype, 'square', {
  get() {
    return this * this;
  }
});
```

---

## Property Chain

```js
(8).double.square;
// 256
```

```js
8['double']['square'];
// 256
```

---

## Key Takeaway

- JavaScript is highly dynamic
- Syntax and object model are deeply flexible
- Clever code is not always good code

---

## Caveat

- Extending built-in prototypes can cause conflicts
- Surprising syntax hurts readability
- Useful for learning; risky in production code
